# Form Garden

Form Garden now includes two complementary tools:

- **Iteration Lab (`dist/`)** — a browser-based teaching studio for prediction, controlled experiments, reflection, saved iterations, and side-by-side comparison.
- **Processing sketch (`*.pde`)** — the original high-detail mesh generator and fabrication-oriented OBJ/STL exporter.

## Open the Iteration Lab

Open `dist/index.html` directly, or serve the folder with any static web server. The browser tool has no dependencies and stores the current study in local browser storage.

Use the workflow in order:

1. Write a prediction in **Before you change it**.
2. Change one growth rule and observe the form.
3. Record evidence in **After you observe**.
4. Choose **Save iteration**.
5. Save a contrasting result, select both cards, and choose **Compare two**.

The lab supports orbit, pan, zoom, four presets, three motifs, deterministic seeds, undo/redo, Processing-compatible JSON recipe import, study export, and a browser OBJ proxy export (Shift-click **Export**). Saved studies include the project title, reflections, thumbnails, recipes, and iteration history.

For final fabrication exports, use the Processing version below; its OBJ/STL writers preserve the full solid geometry described in this document.

A Processing sketch for growing faceted, curling, branching forms from repeated solids. Built by inspecting the supplied OBJ/STL examples. This is a new generative system inspired by their geometry, rather than a reconstruction of the original software's exact rules.

## Open it

1. Extract the ZIP. Keep the `FormGarden` folder and its four `.pde` files together.
2. In **Processing 4, Java mode**, open `FormGarden/FormGarden.pde`.
3. Press **Run**. No contributed libraries are required.
4. Start with preset **1**, then move **Bend**, **Ring twist**, and **Scale / step**. Release a slider to rebuild.

The supplied `preview.png` renders actual meshes generated by the engine; it is not an image-generation mockup or a screenshot of the interface.

| --- | --- |

| Show triangle edges | **W** |
| Automatic rotation | **Space** |
| Save settings | **S** |

| Export OBJ | **E** |
| Export ASCII STL | **T** |

Files go into `FormGarden/exports/`, beside the sketch. Every mesh export also saves a JSON recipe. Filenames include a timestamp and unique suffix. A recipe stores the generator version, all geometry parameters, motif, preset origin, and seed; camera position and display settings are not part of the recipe.

Preset buttons reset all sliders, including export size, to that preset's defaults. They keep the seed. The highlighted preset indicates the starting recipe, even after you edit it.

## How the form grows

A stem carries a local coordinate frame. On each step it:

1. Places a ring of blocks/wedges, or builds a polygon frame with longitudinal and diagonal struts.
2. Advances along its local Z axis.
3. Turns its bend axis and bends toward its local side.
4. Multiplies its size by the taper factor.
5. Optionally spawns a smaller branch at the chosen interval.

Ring twist rotates the emitted cross section independently of the stem's bend. This lets the surface spiral while the larger form follows a clear arc. Bend-axis turn makes that arc wander through three dimensions. Branches are processed in interleaved steps so the first branch cannot consume the whole element budget.

### Parameters that matter most

| Parameter | Effect |
| --- | --- |
| Steps per stem | Length of the growth sequence; child stems have shorter sequences |
| Starting stems | Number of roots sharing the same origin |
| Elements around ring | Facet count or polygon sides |
| Ring radius | Hollow center / overall cross-section size |
| Advance per step | Distance between repeated layers; changes density and overlap |
| Ring twist / step | Rotation of the emitted pattern around the stem |
| Bend / step | Curvature of the growing stem |
| Bend axis turn | Rotates the direction of curvature; creates spatial coils |
| Scale / step | Below 1 shrinks, 1 repeats evenly, above 1 expands exponentially |
| Element width / depth / length | Dimensions of each block or wedge |
| Fork interval / generations / spread / child scale | Branch rhythm, depth, angle, and relative size |
| Angular variation | Seeded irregularity in growth direction |
| Maximum solid elements | Hard complexity limit; the status bar reports truncation |
| Export longest side | Uniformly scales the exported bounding box to this length in millimeters |

Frame mode uses width and depth as strut cross-section dimensions. Element length is unused in frame mode. At radius zero, ring elements coincide and frame edges can collapse; a positive radius gives useful results. Increased advance can deliberately separate blocks. New seeds leave fully deterministic settings unchanged when angular variation is zero.

Useful starting experiments:

- **Tapered horns:** preset 1; taper around 0.98–0.99; bend 1–2 degrees; fewer branches.
- **Expanding curls:** preset 2; taper slightly above 1; larger advance; reduce generations to keep silhouettes readable.
- **Interlocking arcs:** preset 3; set bend-axis turn to zero; raise bend or steps toward a full revolution.
- **Architectural lattice:** preset 4; explore 3–6 sides and ring twist; adjust strut width independently of radius.

## Code map

- `FormGarden.pde`: editable parameter defaults, presets, camera, retained triangle rendering.
- `Growth.pde`: turtle growth rules, branching, mesh primitives, bounds.
- `Interface.pde`: sliders, shortcuts, mouse navigation.
- `Export.pde`: JSON persistence, OBJ and ASCII STL writers.

The parameter array at the top of `FormGarden.pde` is the single source of truth. Each entry specifies key, label, default, minimum, maximum, and whether it is an integer. Preset overrides live in `applyPreset()`.

To change the generative language, edit `generateMesh()` and `advance()` in `Growth.pde`. To introduce a new primitive, extend `Mesh.primitive()` and its indexed triangle definitions. No original models need to be loaded to generate new forms.

## Mesh and fabrication limits

Each emitted block, wedge, or strut is a closed solid with outward-wound triangles. The complete sculpture is a collection of solids: they can overlap, intersect, or become disconnected. **The exporter does not perform boolean union, remeshing, support generation, or printability checks.** It does not guarantee one watertight, connected sculpture. Small intersections and internal faces are intentional consequences of the construction method.

Exports are Z-up, centered in X/Y, and placed with their lowest point at Z=0. The longest bounding-box side, not necessarily the height, matches the export-size slider. OBJ/STL contain numeric coordinates without a universally enforced unit declaration; import them as millimeters. Changing camera or zoom does not change exported dimensions.

Before printing, inspect scale, connectedness, minimum wall/strut thickness after scaling, overhangs, and slicer interpretation of overlapping shells. Boolean union or voxel remeshing in a mesh editor may be appropriate for fabrication. Thin structures and separated blocks need deliberate treatment.

The maximum-element control protects against runaway branching. A capped build can have abruptly ended stems; raise the cap or reduce steps/generations. Export writes synchronously, so high-complexity ASCII STL files can briefly pause the window.

## Verification

The four tabs were compiled together against Processing core 4.3.1 using Java 17. A headless harness exercised all **12 preset × motif combinations**, deterministic regeneration, finite vertices, nonzero triangle areas, positive signed volume, and the element cap. The shipped OBJ/STL exporters and recipe restore were also exercised. The preview was rendered from generated meshes.

The OpenGL window, mouse interaction, and native file picker have not been launched in this environment. These still need a first-run check in your local Processing installation.
